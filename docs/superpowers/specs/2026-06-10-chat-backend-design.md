# 在线实时聊天室后端设计

## 背景与目标

本阶段只实现后端和 API，前端后续再开发。系统用于管理员创建临时聊天室并分享链接，访客点击链接进入后只能看到管理员用户，并与管理员进行一对一实时聊天。

后端使用 Node.js、Express、ws、PostgreSQL 和 TypeScript 开发。系统使用数据库保存管理员信息和聊天室元数据，但不保存聊天记录。

## 核心约束

- `config.js` 中配置的管理员用户名和密码只用于首次登录或数据库中暂无管理员时的引导登录。
- 管理员信息保存到 PostgreSQL，首次登录后可以设置新的管理员用户名和密码。
- 房间基础信息保存到 PostgreSQL，便于服务重启后仍可识别已创建的聊天室。
- 管理员 token、在线连接和会话路由关系保存在 Node 进程内存中。
- 聊天记录不保存在服务端内存中，也不写入文件或数据库。
- 服务端只负责校验、识别会话双方并转发文字和图片消息。
- 聊天记录由管理员浏览器和访客浏览器各自保存在本地内存中，关闭浏览器标签页后消失。
- 除管理员以外的用户名由时间戳生成，避免要求访客填写名称。
- 图片消息初版通过 WebSocket 传递前端压缩后的 dataURL 或 base64 字符串，服务端只做大小和类型校验后转发。

## 后端模块

### 配置模块

`config.js` 保存本地开发配置，包含服务端端口、站点协议、站点域名、PostgreSQL 连接信息和首次登录管理员账号密码。该文件允许写入真实数据，但严禁提交到远程仓库。

后续可提供 `config.example.js` 作为安全模板，只写入占位值，方便协作部署。

### 数据库模块

`src/db/pool.ts` 负责创建 PostgreSQL 连接池，统一管理数据库连接。

`src/db/migrations` 保存数据库迁移脚本，职责是创建管理员表和聊天室表。迁移脚本只管理管理员信息和房间元数据，不创建聊天记录表。

管理员表保存管理员用户名和加密后的密码摘要。聊天室表保存房间 ID、创建者管理员 ID、分享链接标识、创建时间和状态等信息。

### 日志模块

`src/utils/logger.ts` 提供统一日志工具，职责是输出模块名、日志级别和上海时区时间。关键分支包括服务启动、管理员登录成功或失败、房间创建、WebSocket 连接建立和异常断开。

### 鉴权服务

`src/services/authService.ts` 负责校验管理员账号密码，生成管理员内存 token，并校验需要管理员权限的 REST API 和 WebSocket 连接。

校验时优先查询 PostgreSQL 中的管理员记录。如果数据库中暂无管理员，则允许使用 `config.js` 中的首次登录账号密码通过校验，并引导创建数据库管理员。

token 仅存在当前 Node 进程内存中，服务重启后失效。

### 管理员服务

`src/services/adminService.ts` 负责查询、创建和更新管理员账号。新增或修改密码时必须写入密码摘要，不能保存明文密码。

核心分支包括：数据库暂无管理员时创建首个管理员；已有管理员时只允许已登录管理员修改账号密码；用户名重复或密码不符合规则时返回明确错误。

### 房间服务

`src/services/roomService.ts` 负责创建聊天室、生成分享链接、查询房间基础信息，并维护房间与在线连接的关系。

房间基础信息保存到 PostgreSQL，只包含房间 ID、创建时间、管理员标识、分享链接标识和状态等字段，不包含消息内容。在线连接和会话路由关系仍只保存在 Node 进程内存中。

### 聊天转发服务

`src/services/chatRelayService.ts` 负责处理 WebSocket 消息。它只校验消息格式、会话归属和目标连接，然后将消息转发给对端。

该服务不提供消息列表查询能力，不缓存历史消息，也不把消息写入日志正文。日志只记录消息类型、房间 ID、发送方角色和转发结果。

## REST API

### `POST /api/auth/login`

管理员登录接口。请求体包含 `username` 和 `password`。校验通过后返回内存 token 和管理员展示名称。

如果数据库中没有管理员，接口允许使用 `config.js` 的首次登录账号密码登录，并在响应中标记需要初始化或更新数据库管理员。失败时返回 401，并打印警告日志。

### `POST /api/admin/setup`

首次创建数据库管理员接口。仅在数据库中暂无管理员，且请求携带有效首次登录 token 时可调用。请求体包含新的 `username` 和 `password`。

创建成功后，后续登录以数据库管理员信息为准。

### `PUT /api/admin/profile`

管理员更新账号密码接口。请求头使用 `Authorization: Bearer <token>`。请求体可包含新的 `username` 和 `password`。

更新成功后，旧的内存 token 可以立即失效，要求管理员重新登录。

### `POST /api/rooms`

管理员创建聊天室接口。请求头使用 `Authorization: Bearer <token>`。创建成功后将房间基础信息写入 PostgreSQL，并返回房间 ID 和分享链接。

分享链接基于 `config.js` 中的 `site.protocol` 与 `site.host` 生成，供后续前端路由使用。

### `GET /api/rooms/:roomId`

查询房间基础信息接口。访客进入房间前可调用该接口从 PostgreSQL 确认房间存在，并获取管理员展示名称。

该接口不返回在线连接详情和聊天记录。

## WebSocket 协议

连接地址建议为：

`/ws/chat?roomId=<roomId>&role=admin|guest&token=<adminToken>`

管理员连接必须携带 token。访客连接不需要 token，服务端按当前时间戳生成用户名，例如 `用户-1760000000000`。

客户端发送消息示例：

```json
{
  "type": "text",
  "clientMessageId": "local-uuid",
  "payload": {
    "text": "你好"
  }
}
```

图片消息示例：

```json
{
  "type": "image",
  "clientMessageId": "local-uuid",
  "payload": {
    "mimeType": "image/png",
    "dataUrl": "data:image/png;base64,..."
  }
}
```

服务端转发时补充 `serverMessageId`、`roomId`、`from`、`to` 和 `sentAt`，但不保存该消息。

## 会话模型

一个房间允许管理员和多个访客同时在线。访客只能看到管理员，访客之间互相不可见、不可通信。

管理员侧可收到多个访客的消息，前端后续可按访客连接 ID 或访客用户名切换会话。后端只维护“访客连接到管理员连接”的转发关系。

当管理员不在线时，访客可以连接房间，但发送消息会收到管理员离线提示。该提示由服务端即时返回，不作为聊天记录保存。

## 错误处理

- 数据库连接失败：REST 返回 503，并记录错误日志；WebSocket 拒绝新连接。
- token 无效：REST 返回 401，WebSocket 连接关闭并返回鉴权错误。
- 房间不存在：REST 返回 404，WebSocket 拒绝连接。
- 消息格式错误：返回错误事件给当前连接，不转发。
- 图片过大或 MIME 类型不允许：返回错误事件给当前连接，不转发。
- 目标用户离线：返回错误事件给发送方，不缓存待发送消息。

## 测试范围

后端测试覆盖以下行为：

- 管理员账号密码校验和 token 生成。
- 数据库为空时允许使用 `config.js` 首次登录账号。
- 首次登录后可创建数据库管理员，并用数据库账号再次登录。
- 管理员更新账号密码后旧 token 失效。
- 未登录无法创建房间。
- 管理员可创建房间、写入 PostgreSQL 并生成分享链接。
- 服务重启后可从 PostgreSQL 查询已创建房间基础信息。
- 访客进入房间时自动生成时间戳用户名。
- 文本消息只转发给对端，不写入服务端历史列表。
- 图片消息校验通过后只转发，不落盘、不缓存。
- 管理员离线时访客发送消息收到错误事件。

## 非目标

- 不做服务端聊天记录查询。
- 不做多进程或多实例房间同步。
- 不做图片文件上传和静态文件托管。
- 不做访客注册、登录或自定义用户名。
- 本阶段不实现 Vue 前端界面。
